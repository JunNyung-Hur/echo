# echo v0.0.5

This bug-fix release corrects the distinction between an empty freeform notebook
and an unavailable note body.

## Changes

- An empty freeform notebook is a valid writing destination. The agent receives
  an empty successful read and guidance to use `write_note` for the first content,
  without requiring a title or another notebook creation step.
- Reading an empty notebook does not create a body. Questions can be answered
  without creating note content.
- Missing notebooks, missing content files, and in-progress generation remain
  distinct from a valid empty notebook. Existing content and version IDs are
  returned unchanged.
- Release automation selects notes from the tagged version, checks each build/test
  command for failure, and pins FFmpeg to a dated LGPL build and SHA-256 digest.

## Compatibility

No database migration or storage-path change is introduced. Existing notes,
manual edits, version history, and transcript access remain in place.
The broader conversation-workflow redesign is a proposal, not part of this release.

## Verification

Local core regression tests: **20 passed, 0 failed, 1 ignored**. The ignored test
requires a configured real model. TypeScript checking also passed.
The Windows release workflow runs the frontend build, core and native Rust tests,
and application check before producing EXE/MSI installers and SHA-256 checksums.

Real desktop UI and model-mediated scenario testing was deferred for this release
at the maintainer's request. It has not been performed or counted as passing;
no measured end-to-end note-quality improvement is claimed.

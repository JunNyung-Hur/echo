# echo v0.0.6

This release improves request continuity, note-writing guidance and model compatibility.

## Changes

- User requests are indexed with their source references, individual tool outcomes
  and turn termination state. A successful edit is not treated as proof that an
  entire multi-part request is complete. Current questions and changed requests
  take priority over earlier work.
- Conversation history, existing notes and transcripts are all supported as
  evidence. Failed historical reads remain failures when context is shortened.
- Saving a user message and linking its recordings is atomic. History-read errors
  stop the request instead of silently becoming an empty conversation.
- Failed audio attachments no longer discard independent text requests. Theme
  changes no longer instruct the agent to abandon other requested work.
- Empty model responses are rejected. Unknown stages do not grant edit tools;
  question tools respect capability restrictions.
- Failed note generation selects its original transcript rather than substituting
  another completed recording from the same note.
- Writing guidance preserves explanations, examples and qualifications while
  discouraging repeated summaries and unsupported expansion.
- Pathological repetition in ASR output, including cached output, causes the affected
  chunk to be retried. Persistent failure uses the existing incomplete-transcript
  handling. This is a limited repetition detector, not general ASR quality scoring.
- GPT reasoning models omit the fixed temperature option. Model choices include
  GPT-5.4 and GPT-5.6 Luna, Terra and Sol.

## Compatibility and verification

No database migration is required. Existing notes and source files are not rewritten
by installing this version. Additional intent/continuity and transport/database
regression cases are included.

Local validation was limited to source inspection, diff checks and JSON validation;
Rust compilation and real desktop/model scenarios were not run locally. No measured
note-quality improvement or complete prevention of intent errors is claimed.
The release workflow must pass frontend build, core and desktop tests, and application
checking before it builds and publishes Windows EXE/MSI installers and checksums.
Build and workflow results are not polled by the agent.
